# 要求定義書 / Requirements — 土器破片接合シミュレーションシステム

## 背景
複数の土器破片を3Dスキャナーでスキャンしたデータ（メッシュ・点群）を入力し、
破片同士の破断面形状の類似性に基づいて接合関係・接合姿勢を推定し、
仮想的に破片を組み立てる（接合シミュレーションを行う）システムを開発する。
複数器物の破片が混在する状況を想定し、器物ごとのグループ分けから
完全自動推定、および人間による確認・微調整までを支援する。

## 用語
- 破片(Fragment): 3Dスキャンされた個々の土器片データ（メッシュまたは点群）。
- 器物(Vessel): 複数の破片から構成される元の一つの土器個体。
- 接合候補(Match Candidate): 破断面形状の類似性により推定された、隣接し得る破片ペアと相対姿勢。
- 姿勢(Pose): 破片を3D空間に配置するための変換行列（回転・並進）。

## REQ-POTTERY-001: スキャンデータのインポート
Priority: must
Type: functional
Pattern: ubiquitous
Statement: システムは、STL形式、頂点色・テクスチャ座標付きOBJ形式（関連MTLファイルを含む）、および法線・RGB色を含みうる生の点群形式（XYZ/PCD相当）で保存された破片の3Dスキャンデータを、ファイル自体に単位情報がない場合に既定単位ミリメートルとみなし、利用者が明示的に指定した場合にその単位で換算した上でインポートしなければならない。
Acceptance: 単位情報を持たないSTL/OBJ/点群ファイル、およびセンチメートル単位を明示指定したファイルをそれぞれ入力し、前者は既定でミリメートルとして、後者は指定単位からミリメートルへ換算されて取り込まれることをテストで確認する。あわせて、ジオメトリ・法線・色/テクスチャ属性が保持されたまま読み込まれることを確認する。

## REQ-POTTERY-002: 不正・破損データの検出
Priority: must
Type: functional
Pattern: unwanted-behavior
Statement: もし読み込んだスキャンデータが破損している、対応形式でない、または必須のジオメトリ情報を欠いているならば、システムは他の読み込み済み破片を維持したまま、当該ファイルをエラーとして報告しなければならない。
Acceptance: 破損させたファイル、非対応拡張子のファイル、ジオメトリ情報を欠くファイルをそれぞれ入力し、既に読み込み済みの他破片が維持されたまま、当該ファイルのみエラーとして報告されることをテストで確認する。

## REQ-POTTERY-003: 器物ごとの自動グルーピング
Priority: must
Type: functional
Pattern: event-driven
Statement: 複数の器物に由来する可能性がある破片が読み込まれたとき、システムはクラスタ所属信頼度（0以上100以下、値が大きいほど所属確度が高い）が70以上となる破片を器物候補ごとにグルーピングし、70未満の破片を未分類破片として区別しなければならない。
Formal: {"kind":"numeric","metric":"clustering.agreementRate","operator":">=","value":95}
Acceptance: 固定版ベンチマークデータセットPFR-BENCH-CLUSTER-001（正解ラベル付き複数器物混在破片群）に対しグルーピングを実行し、正解ラベルとの一致率が95%以上であること、および所属信頼度70未満の破片が未分類破片として区別されることをテストで測定する。

## REQ-POTTERY-004: 破断面接合候補の自動推定
Priority: must
Type: functional
Pattern: event-driven
Statement: 器物候補ごとの破片群が確定したとき、システムは破断面形状の一致度に基づき、破片の組ごとに信頼度が最も高い1件の推定接合姿勢のみを接合候補として算出しなければならない。
Acceptance: 正解接合関係が既知のテストデータセットに対し接合候補を算出し、同一破片の組に対して出力される候補が常に1件のみであること、および算出された接合候補ペアの適合率をテストで測定する。

## REQ-POTTERY-005: 色・模様情報を用いた接合精度向上
Priority: must
Type: functional
Pattern: state-driven
Statement: 破片に色・模様（テクスチャ）情報が付与されている間、システムは形状類似度に加えて色・模様の連続性を接合候補の評価に利用しなければならない。
Acceptance: 同一形状で模様が異なる破片ペアを含むテストデータセットに対し、模様情報利用時と未利用時で誤接合の減少をテストで比較する。

## REQ-POTTERY-006: 完全自動組み立てモード
Priority: must
Type: functional
Pattern: event-driven
Statement: 利用者が完全自動モードを選択したとき、システムは推定した接合候補のうち信頼度スコア70以上（REQ-POTTERY-018の採用閾値と同一）を満たすものを信頼度降順（同点の場合は破片ID対の昇順）に走査し、既に採用した候補とREQ-POTTERY-027の基準で姿勢矛盾しない候補のみを器物ごとに順次採用し、矛盾により却下した候補を却下候補として区別して報告した上で、接合関係が確定した破片のみを自動配置した組み立て結果として生成しなければならない。
Acceptance: 未接合破片、および閉路をなす3破片ペア（採用済みのA-BとB-Cから伝播したAの姿勢に対し、単独では信頼度スコア70以上となるが姿勢がREQ-POTTERY-027の基準を超えて矛盾するA-C）を含むテストデータセットに対して完全自動モードを実行し、生成された組み立て結果にはA・B・Cの全破片が信頼度降順の走査で先に採用されたA-B・B-Cの接合関係で含まれること、これと矛盾するA-Cは採用されず却下候補として区別されて報告されること（フラグメントの未接合判定ではない）、また別途用意した接合先のない破片が未接合破片一覧（REQ-POTTERY-009）に含まれ組み立て結果には含まれないことをテストで確認する。

## REQ-POTTERY-007: 半自動（候補提示）モード
Priority: must
Type: functional
Pattern: event-driven
Statement: 利用者が半自動モードを選択したとき、システムは各接合候補ペアについて推定信頼度の数値および根拠（形状・色模様）とともに信頼度順に一覧表示し、利用者が候補の採否および配置姿勢を選択できるようにしなければならない。
Acceptance: 半自動モードを実行し、信頼度の数値・根拠とともに信頼度順に並んだ候補一覧が表示され、利用者の採用・却下操作が組み立て結果に反映されることをUIテストで確認する。

## REQ-POTTERY-008: 人手による微調整
Priority: must
Type: functional
Pattern: event-driven
Statement: 利用者が3D空間上で破片をドラッグ操作等により移動・回転させたとき、システムは当該破片の姿勢を更新し、隣接破片との隙間・重なりを再評価して表示しなければならない。
Acceptance: 手動操作で破片を移動・回転させ、隙間・重なり量の表示値が操作に追随して更新されることをテストで確認する。

## REQ-POTTERY-009: 未接合破片の報告
Priority: must
Type: functional
Pattern: ubiquitous
Statement: システムは、接合候補が採用されなかった破片を未接合破片一覧として表示し、既定の統合メッシュ出力の対象から除外しなければならない。
Acceptance: 接合先が存在しない破片を含むデータセットを入力し、当該破片が未接合一覧に含まれ、既定の統合メッシュ出力（REQ-POTTERY-011）には含まれないことをテストで確認する。

## REQ-POTTERY-010: 欠損部分の推定
Priority: should
Type: functional
Pattern: optional-feature
Statement: 器物が回転成形による回転対称形状と判定でき欠損部分推定機能が有効な場合、システムは残存破片の輪郭から回転対称性を利用して欠損部分の概形を推定した独立の推定形状レコードとして生成し、実測破片データと区別可能な形で結果に反映しなければならない。
Acceptance: 一部破片を意図的に除去した回転対称形状のテストデータに対し、推定された欠損概形が実破片データとは別の推定形状レコードとして出力され、実測データと区別可能な表示・出力属性を持つこと、および推定された欠損概形と実際に除去した形状との形状誤差をテストで測定する。

## REQ-POTTERY-011: 組み立て結果の統合メッシュ出力
Priority: must
Type: functional
Pattern: event-driven
Statement: 利用者が組み立て結果の確定を指示したとき、システムは接合関係が確定した破片のみを統合した三次元メッシュをSTLまたはOBJ形式でエクスポートしなければならない。
Acceptance: 未接合破片を含むデータセットで組み立て結果を確定しエクスポートを実行し、出力ファイルに接合関係が確定した破片のみが含まれ未接合破片が含まれないこと、また指定形式で生成され外部3Dビューアで開けることをテストで確認する。

## REQ-POTTERY-012: 破片配置・姿勢データの出力
Priority: must
Type: functional
Pattern: event-driven
Statement: 利用者が組み立て結果の確定を指示したとき、システムはインポート済みの全破片について、識別子、変換行列、および接合状態（確定済み・未接合のいずれか）を含むデータを出力しなければならない。
Acceptance: 確定済み・未接合の破片を含むデータセットに対しエクスポートを実行し、出力データにインポート済み全破片分の識別子・変換行列・接合状態（確定済み/未接合）が含まれることをテストで確認する。推定欠損部分の形状データはREQ-POTTERY-010が定める独立の推定形状レコードとして別途出力され、本要求の対象（インポートされた実破片）には含まれない。

## REQ-POTTERY-013: 接合箇所・一致度レポート出力

Acceptance: 出力レポートに全接合箇所と対応する一致度スコアが記載されていることをテストで確認する。

Acceptance: 組み立て結果を表示し、視点操作の各操作（回転・拡大縮小・移動）が反映されることをテストで確認する。

## REQ-POTTERY-015: プロジェクトの保存・再開
Priority: must

Acceptance: プロジェクトを保存し、システムを再起動して読み込んだ際に、保存時点の状態（配置・編集内容・クラスタリング/接合推定結果を含む）が復元されること、および参照先スキャンデータのハッシュが保存されていることをテストで確認する。
