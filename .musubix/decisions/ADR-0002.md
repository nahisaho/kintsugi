# ADR-0002: デスクトップGUI・実装技術スタックの選定

## Context / 背景
土器破片接合シミュレーションシステム（pottery-fragment-reassembly）は、REQ-POTTERY-016
（オフライン動作必須）、REQ-POTTERY-017（Windowsデスクトップ GUI として提供）、
REQ-POTTERY-019（固定ベンチマーク環境で破片100点を60分以内に処理）という制約の下で、
点群・メッシュレジストレーション（ICP等）を含む計算負荷の高い幾何処理と、
3Dビューア（REQ-POTTERY-014、回転・拡大縮小・移動操作）を伴うインタラクティブな
デスクトップGUIの両方を提供する必要がある。

## Decision / 決定
計算コアはC++で実装し、点群・メッシュ処理には既存の実績あるオープンソース幾何処理
ライブラリ（Point Cloud Library相当のレジストレーション・特徴量抽出機能）を利用する。
GUI・3DビューアはQt（デスクトップウィジェット）+ VTKベースの3Dビューポートで構築し、
ネットワーク接続を前提とする外部サービス呼び出しを一切行わない構成とする。

## Rejected Alternatives / 却下した代替案
- **Electron + WebGLベースの実装**: Webブラウザランタイムに依存するため、100点規模の
  点群・メッシュレジストレーション処理でネイティブC++実装に比べCPU・メモリのオーバー
  ヘッドが大きく、REQ-POTTERY-019の60分処理上限達成の確実性が下がる。
- **.NET（C#）+ Helix Toolkit**: GUI構築は容易だが、点群レジストレーション・特徴量
  抽出のための成熟したオープンソースエコシステムがC++系ライブラリに比べて薄く、
  自前実装コストが増大する。
- **Unity3D等のゲームエンジン**: 3D描画は容易だが、研究用途の幾何解析ツールとしては
  オーバースペックであり、オフライン配布時のライセンス条件確認コストが増える。

## Consequences / 結果
C++コア＋Qt/VTK GUIの構成により、レジストレーション処理の性能とネイティブ3D描画の
両立が可能になる一方、UI実装の生産性はWeb系フレームワークより低くなるため、UI層は
明確なインターフェース境界（DES-POTTERY-009）で計算コアから分離し、UI変更が計算コア
の性能特性に影響しないようにする。
